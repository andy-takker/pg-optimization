## Сводка по трём режимам автовакуума (профиль update+delete, pgbench -c4 -T180)

Режим    | autovacuum_count | mean TPS | stddev | CV TPS | трактовка
---------+------------------+----------+--------+--------+-----------------------------
default  |        3         |  412.7   | 126.8  | 30.7%  | пила: копит ~400k мёртвых -> сброс
rare     |        0         |  241.1   | 124.6  | 51.7%  | блоат + деградация (нет чистки)
tuned    |       18         |  599.8   |  65.8  | 11.0%  | ровно и быстро (частые мелкие чистки)

# CV = коэффициент вариации TPS (мера «пилы»), считается по ряду pgbench -P 5.

## n_dead_tup, ключевые точки (тыс. строк)
# default: пила 0 -> 403 -> сброс -> 400 -> сброс -> 400 -> сброс (3 автовакуума)
# rare:    монотонный рост 0 -> 753 (автовакуум не запускался ни разу)
# tuned:   частые мелкие сбросы, держится в коридоре ~0..193 (18 автовакуумов) при росте живых строк до ~7.3M

## Per-table тюнинг (решение из ДЗ)
ALTER TABLE t SET (autovacuum_vacuum_scale_factor=0.01, autovacuum_vacuum_threshold=100, autovacuum_analyze_scale_factor=0.01);
ALTER SYSTEM SET autovacuum_max_workers=4, autovacuum_naptime='10s', autovacuum_vacuum_cost_limit=2000;

## Вывод
# Цель «равномерной нагрузки» достигается НЕ выключением/замедлением автовакуума,
# а наоборот — заставить его работать ЧАЩЕ и меньшими порциями (низкие пороги, naptime 10s,
# больше cost_limit). Тогда мёртвые строки не накапливаются до больших пачек, и пила TPS исчезает.
# Бонус: tuned дал и самый высокий средний TPS — лёгкая таблица = эффективнее кеш и сканы.
